# SPEC.md — Job Application Copilot

> เขียนสเปกนี้ก่อนเริ่มเขียนโค้ด (Spec-Driven Development) ตามโจทย์ GSP1150 Day 2

## 1. โจทย์ / ปัญหาที่แก้

เวลาสมัครงาน ผู้สมัครส่วนใหญ่ไม่รู้ว่า:
- เรซูเม่ของตัวเอง "แมตช์" กับประกาศงานแค่ไหน
- ควรเน้นจุดแข็งข้อไหน และต้องเตรียมตอบจุดอ่อนข้อไหน
- บริษัทนี้ทำธุรกิจอะไร มีข่าวอะไรล่าสุดที่ควรรู้ก่อนสัมภาษณ์
- คำถามสัมภาษณ์ที่มักถูกถามสำหรับตำแหน่งนี้คืออะไร

**Job Application Copilot** แก้ปัญหานี้โดยรับ "ประกาศงาน" + "เรซูเม่" + "ชื่อบริษัท" แล้ว:
1. ค้นข้อมูลบริษัทล่าสุดจริง ๆ ด้วย Google Search grounding
2. คำนวณอายุงานจริงจากเรซูเม่ด้วย function calling (ไม่ใช่ให้โมเดลเดาเอง)
3. วิเคราะห์ความเหมาะสมออกมาเป็น JSON โครงสร้างชัดเจน
4. เปิดโหมดซ้อมสัมภาษณ์แบบสนทนาโต้ตอบจริง (multi-turn + streaming)

## 2. Input / Output

### Input
| Input | รูปแบบ | ตัวอย่าง |
|---|---|---|
| ประกาศงาน | ไฟล์ .txt หรือ path | `samples/sample_job.txt` |
| เรซูเม่ผู้สมัคร | ไฟล์ .txt หรือ path | `samples/sample_resume.txt` |
| ชื่อบริษัท | string | `"Krungthai Bank"` |
| โหมดโต้ตอบ | flag `--interactive` | ถ้าใส่ จะเปิดแชทซ้อมสัมภาษณ์ต่อท้าย |

### Output
1. `output/analysis.json` — ผลวิเคราะห์แบบ JSON (ดู schema ด้านล่าง)
2. Terminal แสดงผลวิเคราะห์แบบอ่านง่าย
3. (ถ้า `--interactive`) บทสนทนาซ้อมสัมภาษณ์แบบ streaming ในเทอร์มินัล

### JSON Schema ของผลวิเคราะห์ (structured output)
```json
{
  "match_score": 0-100,
  "summary": "string",
  "strengths": ["string", "..."],
  "gaps": ["string", "..."],
  "recommended_skills_to_learn": ["string", "..."],
  "estimated_years_experience": 0.0,
  "interview_questions": [
    {"category": "string", "question": "string", "tip": "string"}
  ]
}
```

## 3. System Instructions ที่ออกแบบ

**บทบาทที่ 1 — นักวิเคราะห์ใบสมัคร (ใช้ตอนสร้าง JSON):**
> "คุณคือนักวิเคราะห์ HR มืออาชีพที่ตรงไปตรงมาแต่ให้กำลังใจ วิเคราะห์อย่างเป็นกลางบนหลักฐานจากเรซูเม่และประกาศงานเท่านั้น ห้ามเดาข้อมูลที่ไม่มีในเอกสาร ตอบเป็น JSON ตาม schema ที่กำหนดเท่านั้น"

**บทบาทที่ 2 — โค้ชซ้อมสัมภาษณ์ (ใช้ตอนแชท):**
> "คุณคือโค้ชเตรียมสัมภาษณ์งานที่เป็นกันเอง ถามทีละคำถาม ฟังคำตอบผู้ใช้แล้วให้ feedback สั้น กระชับ ทันที ก่อนถามคำถามถัดไป ให้กำลังใจแต่ตรงประเด็น"

## 4. Prompt Design (สรุป)

- Call 1 (Grounding): สั่งให้ค้นข้อมูลบริษัทล่าสุด สรุป bullet 5-8 ข้อ
- Call 2 (Function calling): ส่งเรซูเม่ให้โมเดลดึงช่วงเวลาทำงาน (start/end) แล้วเรียก `calc_years_experience`
- Call 3 (Structured output): รวมประกาศงาน + เรซูเม่ + ผลค้นบริษัท + อายุงานที่คำนวณได้ → ขอ JSON ตาม schema
- Call 4 (Multi-turn chat streaming): ใช้ผลจาก Call 3 (โดยเฉพาะ gaps และคำถามข้อแรก) เป็น context เริ่มบทสนทนา

## 5. Temperature ที่เลือกใช้ (เหตุผลอธิบายเพิ่มใน README)

| ส่วน | Temperature | เหตุผลสั้น ๆ |
|---|---|---|
| Grounding ค้นข้อมูลบริษัท | 0.3 | ต้องการข้อเท็จจริง แต่ยอมให้สรุปมีความลื่นไหลได้บ้าง |
| Function calling ดึงช่วงเวลา | 0.0 | ต้องแม่นยำ/deterministic เต็มที่ ไม่ต้องการความคิดสร้างสรรค์ |
| Structured output วิเคราะห์ | 0.2 | ต้องการผลที่ตรวจสอบได้ ทำซ้ำได้ ไม่อยากให้คะแนน/สรุปแกว่งมาก |
| Interview chat coach | 0.7 | ต้องการความเป็นธรรมชาติ หลากหลายคำถาม/น้ำเสียงเหมือนคนจริง |

## 6. ฟีเจอร์เสริม (Determination)

- **Multi-turn chat + Streaming**: โหมด `--interactive` ใช้ `chat.send_message_stream()` จำบริบทตลอดการซ้อมสัมภาษณ์
- **thinking_level comparison**: flag `--compare-thinking` รันการวิเคราะห์เดียวกันด้วย thinking level ต่างกัน 2 ระดับ แล้วพิมพ์เปรียบเทียบเวลา/ผลลัพธ์

## 7. ขอบเขตที่ไม่ทำ (Out of scope)

- ไม่มี UI เว็บ (เป็น CLI/Python script ตามโจทย์)
- ไม่เชื่อมต่อระบบ ATS จริง
- ไม่ตรวจสอบว่าข้อมูลบริษัทจาก grounding เป็นข้อมูลลับ/เป็นทางการ 100% (ผู้ใช้ควรตรวจสอบซ้ำ)
